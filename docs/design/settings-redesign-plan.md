# AIbox Mobile Android 设置页重设计与实施方案

> **版本**：v2.0  
> **日期**：2026-09-25  
> **目标平台**：Android（Capacitor WebView，API 23–35）  
> **实施状态**：第一版已落地

## 1. 方案结论

本次不新建 React Native 组件库，也不引入新的设置状态管理。AIbox Mobile 的 Android 界面运行在 Capacitor WebView 中，设置页使用 React + Mantine + Tailwind，设置数据由现有 `useSettingsStore` 持久化。因此重设计采用“保留行为、重组层级、渐进披露”的方案：只调整 `src/renderer/routes/settings/general.tsx` 的页面结构和视觉层级，继续复用已有设置字段、主题变量、备份恢复流程和国际化键。

目标是让常用设置更容易找到，同时不隐藏或破坏数据恢复、备份和诊断能力。

## 2. 现有问题与改进目标

### 已确认的问题

- 显示类设置、交互设置和数据工具混在多个相似卡片中，首屏扫描成本高。
- 语言、字体、主题、配色和字体大小之间的关联不够明显。
- 移动端行项目虽然可用，但选择器、颜色预设和自定义颜色编辑区域在窄屏上不够舒展。
- 代理、数据恢复、备份恢复和诊断日志属于低频或高级操作，却与常用设置拥有相同视觉权重。
- 现有页面改造必须兼容桌面端，不能使用 Android 专属原生组件替换共享渲染层。

### 本版目标

1. 常用设置优先：显示和交互设置直接可见。
2. 分组清晰：每组使用标题、图标和卡片层级区分。
3. 移动优先：窄屏下控件自动换行，颜色编辑改为单列，触控区域不小于现有组件的可用尺寸。
4. 高级功能渐进披露：代理、恢复、备份和日志默认收起，但保持明确入口。
5. 行为不变：不改变设置字段、存储格式、恢复逻辑或桌面端系统设置。
6. 不新增翻译负担：优先复用现有国际化键，避免只为 Android 新增英文硬编码文案。

## 3. 页面信息架构

```text
常规设置
├── Display Settings（显示设置）
│   ├── Language
│   ├── Font Family
│   ├── Theme
│   ├── Color Presets / 自定义颜色
│   └── Font Size
│
├── Startup Page（启动页与交互）
│   ├── Home Page / Last Session
│   └── Haptic feedback during generation（仅移动端）
│
├── Advanced Settings（默认折叠）
│   ├── Network Proxy
│   ├── Data Recovery
│   ├── Data Backup and Restore
│   └── Diagnostic Logs / 可选匿名分析
│
└── System（仅桌面端保留）
```

### 为什么不把所有项目都放入“高级”

数据恢复和备份属于低频操作，但涉及用户数据，不能通过难以发现的入口完全隐藏。因此高级区域采用可见的折叠卡片，并在折叠状态下直接列出包含的功能；用户知道功能存在，也不会被长说明文字打断常用设置。

## 4. 视觉与交互规范

### 4.1 容器层级

- 页面继续使用项目现有 `chatbox-*` 背景、边框和文字 token，确保浅色/深色主题一致。
- 一级区域使用现有圆角边框卡片。
- 显示设置中的每个主要项目使用轻量内层卡片，增强移动端分组感，但避免高 elevation 和额外阴影。
- 使用 `p="sm"` / `p="md"` 响应式内边距，窄屏优先减少横向占用。

### 4.2 控件策略

- 语言、字体和主题继续使用 `AdaptiveSelect`，不改现有数据模型。
- 自定义颜色预设继续支持内置预设、自定义预设、编辑、删除和新建；窄屏时编辑区使用单列布局。
- 字体大小在同一张卡片内同时显示当前像素值和滑块。
- 启动页使用现有 `Radio.Group`；触觉反馈使用现有 `Switch`，仅移动端显示。
- 高级区域使用 `Collapse`，按钮通过 `aria-expanded` 和唯一 `aria-controls` 关联内容，支持键盘和屏幕阅读器。

### 4.3 保留的桌面行为

桌面端的启动项、自动更新和 Beta 更新仍位于 `System` 区域；Android 不显示这些选项。这样共享页面不会误把桌面能力暴露到移动端。

## 5. 已实施改动

### 页面结构

已更新 `src/renderer/routes/settings/general.tsx`：

- 将“显示设置”整理为语言、字体、主题、配色、字体大小。
- 将启动页和移动端触觉反馈独立为一个交互区域。
- 将代理、数据恢复、备份恢复、诊断日志和匿名分析统一放入默认折叠的“Advanced Settings”。
- 保留桌面端 `System` 区域和原有条件渲染。

### 移动适配

- 页面边距从固定 `md` 调整为 `sm` 到 `md` 的响应式值。
- 颜色预设按钮最小高度调整为 32px，编辑颜色的双列网格在窄屏下切换为单列。
- 高级区域内容中的输入框和数据操作继续允许在小屏幕上自然换行。
- 没有添加 Android 专用 CSS、原生插件或平台判断以外的新分支。

### 数据与兼容性

- 没有新增设置字段。
- 没有改变 `useSettingsStore`、迁移逻辑、备份格式或 SQLite/Keystore 行为。
- 没有修改生成文件和 Android Gradle 文件。
- 现有的自定义颜色预设、主题色解析和字体设置全部保留。

### 已执行

```text

corepack pnpm run check
```

两项均通过。

### 提交前建议执行

```text

corepack pnpm run test
```


重点手工检查：

- Android 窄屏、深色模式和系统字体放大。
- 展开/收起高级设置后的滚动位置。
- 语言、主题、字体大小、启动页和触觉反馈是否即时保存。
- 自定义颜色预设的新建、编辑、删除和重置。
- 代理输入、数据恢复、备份恢复和日志导出没有回归。
- TalkBack/键盘焦点能识别高级区域的展开状态。

## 7. 后续迭代边界

本版先不做以下高风险扩展：

- 不引入 Android 12 动态配色桥接。当前主题系统仍由 Web 渲染层管理。
- 不把设置拆成多个新路由，避免移动端返回栈和深链接行为发生变化。
- 不新建独立 settings store，不复制现有设置字段。
- 不把数据恢复、备份恢复做成不可见的二级页面。

如果实际模拟器验证后仍觉得页面过长，下一步优先考虑将“数据恢复 / 备份恢复 / 诊断日志”拆为独立设置子路由，而不是继续增加折叠层级。
